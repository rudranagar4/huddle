## 1. Project Overview

**HUDDLE** is a unified campus-life mobile application built for college students. Today, campus information and student engagement are fragmented across WhatsApp groups, Discord servers, notice boards, Instagram pages, and campus portals. 

HUDDLE fixes this fragmentation by centralizing college life into one cohesive ecosystem:
- **Study-Buddy Matching**: Connecting students with compatible study partners based on courses, subjects, schedules, and learning preferences.
- **Campus Events**: A centralized calendar for discovering, registering for, and bookmarking academic, cultural, and club events.
- **Student Communities**: Interest- and department-based clubs and circles that students can explore, join, and stay active in.
- **Collaborative Learning & Quizzes**: Subject-specific quizzes with instant scoring and attempt history to keep study groups sharp.
- **Shared Backend**: The Flutter mobile app communicates directly with the centralized Serverpod backend, which also powers the web version.

## 2. Recommended Architecture

### 2.1 Project Monorepo Structure (Serverpod Standard)
When initialized with `serverpod create huddle`, Serverpod creates a clean 3-part monorepo:
```
microsoft huddle/
├── HUDDLE_FEATURES.md             # This blueprint and tracking document
├── huddle_server/                 # Backend server (Serverpod, endpoints, models, DB migrations)
│   ├── lib/
│   │   ├── src/
│   │   │   ├── endpoints/         # Serverpod API endpoints
│   │   │   ├── models/            # YAML data models (.spy.yaml)
│   │   │   ├── future_calls/      # Scheduled backend tasks
│   │   │   └── generated/         # Code auto-generated by Serverpod CLI
│   │   └── server.dart            # Server entrypoint & configuration
│   └── config/
│       ├── development.yaml       # Database, Redis, and port configurations
│       └── passwords.yaml         # Secret keys (never committed to Git)
├── huddle_client/                 # Shared client library auto-generated from server
│   └── lib/
│       └── huddle_client.dart     # Type-safe Dart client consumed by Flutter & Web
└── huddle_flutter/                # Flutter Mobile Application
    ├── lib/
    │   ├── main.dart              # App bootstrap & Serverpod client initialization
    │   ├── core/                  # Core constants, themes, network clients, utilities
    │   │   ├── theme/             # Design system (Navy, Violet, Teal palette, typography)
    │   │   ├── constants/         # App constants, assets, route names
    │   │   └── utils/             # Formatters, validators, error handlers
    │   ├── features/              # Feature-first modular organization
    │   │   ├── auth/              # Registration, Login, Session Management
    │   │   ├── profile/           # Student profile, Preferences, Edit Profile
    │   │   ├── dashboard/         # Aggregated overview screen
    │   │   ├── study_buddy/       # Buddy discovery, Match algorithm, Study requests
    │   │   ├── events/            # Campus events listing, Details, Registration
    │   │   ├── communities/       # Communities directory, Join/Leave, Member lists
    │   │   ├── quizzes/           # Subject quizzes, Runner, Results & History
    │   │   ├── notifications/     # Activity alerts & reminders
    │   │   └── bookmarks/         # Saved events & buddies
    │   ├── navigation/            # Bottom navigation bar, App router
    │   └── shared/                # Reusable UI widgets (cards, badges, buttons, state views)
    └── pubspec.yaml
```

### 2.2 State Management
- **Recommended**: `flutter_riverpod` or `provider` for robust, testable state injection and reactivity without boilerplate.
- **Data Flow**:
  1. UI triggers an action in a Notifier / Controller.
  2. Controller calls the singleton `huddle_client.Client`.
  3. Serverpod serializes typed requests over WebSockets/HTTP.
  4. Response is unpacked into strongly-typed Dart model classes generated by Serverpod.
  5. UI updates via reactive state binding.

### 2.3 Shared Backend & Website Interoperability
- Both the **Flutter Mobile App** and the **Website** connect to the identical Serverpod backend (`http://localhost:8080/` in dev, Serverpod Cloud URL in production).
- Because Serverpod automatically generates `huddle_client`, web and mobile share the exact same models, endpoints, and authentication tokens with zero drift.

## 4. Setup Problems Found & Step-by-Step Fixes

### Problem 1: Docker Desktop Backend Error (Hardware Virtualization in BIOS)
- **Diagnostic Result**: `WSL 2 is unable to start since virtualization is not enabled on this machine.`
- **Cause**: Windows feature `VirtualMachinePlatform` is enabled, but hardware CPU virtualization (VT-x / AMD-V) is turned off in the motherboard BIOS/UEFI.
- **Fix (Option A - Enable BIOS Virtualization)**:
  1. Restart your PC.
  2. Repeatedly press `F2`, `F10`, `Del`, or `Esc` during boot to enter BIOS/UEFI.
  3. Locate **Virtualization Technology** (Intel VT-x) or **SVM Mode** (AMD CPU) and set to **Enabled**.
  4. Save & Exit (`F10`). Docker Desktop will start automatically.
- **Fix (Option B - Native or Hosted PostgreSQL without Docker)**:
  - If you cannot access BIOS immediately, Serverpod does **not** strictly need Docker. We can configure `huddle_server/config/development.yaml` to point to a local PostgreSQL service on Windows or a free hosted PostgreSQL database (such as Neon or Supabase DB).

### Problem 2: Android SDK Licenses Not Accepted
- **Diagnostic Result**: `flutter doctor` reports unaccepted Android licenses.
- **Fix Command**:
  ```powershell
  flutter doctor --android-licenses
  ```
  *(Press `y` to accept each license).*

### Problem 3: Serverpod Project Not Yet Initialized

## 5. Prioritized, Incremental Implementation Plan

### Step 1: Serverpod Setup + Data Models (Foundation)
- Create the Serverpod project (`serverpod create huddle`).
- Define YAML schemas in `huddle_server/lib/src/models/`:
  - `student_profile.spy.yaml` (name, course, year, subjects, interests, study preferences, bio)
  - `study_request.spy.yaml` (senderId, receiverId, status: pending/accepted/declined, timestamp)
  - `campus_event.spy.yaml` (title, description, category, date, venue, fee, organizer, capacity)
  - `event_registration.spy.yaml` (eventId, studentId, registrationDate)
  - `community.spy.yaml` (name, description, category, memberCount, imageUrl)
  - `community_member.spy.yaml` (communityId, studentId, joinedDate)
  - `quiz.spy.yaml` & `quiz_question.spy.yaml` & `quiz_attempt.spy.yaml`
- Run `serverpod generate` to generate client models and SQL migrations.

### Step 2: Authentication & Profile Engine
- Implement Serverpod Auth integration (`huddle_server/lib/src/endpoints/auth_endpoint.dart` and `profile_endpoint.dart`).
- Implement user authorization checks (students can only modify their own profile data).
- In Flutter: create secure session storage and Profile Provider.

### Step 3: Design System & Navigation Shell
- Implement `HuddleTheme` in Flutter:
  - Background/Navy: `#0A192F` and `#0F172A`
  - Primary Violet: `#6366F1` / `#7C3AED`
  - Accent Teal: `#14B8A6` / `#0D9488`
  - Card/Surface: `#1E293B`
- Build reusable UI atoms: `HuddleCard`, `HuddleButton`, `HuddleBadge`, `HuddleAvatar`, `HuddleTextField`.
- Build `HuddleNavigationShell` with bottom navigation:
  - 🏠 Dashboard
  - 👥 Study Buddies
  - 📅 Events
  - 🏛️ Communities
  - 👤 Profile

### Step 4: Dashboard Screen (MVP Core)
- Aggregate dashboard endpoint (`dashboard_endpoint.dart`).
- Displays greeting, quick stats, top 3 matched study buddies, upcoming registered events, active study requests banner.
- Responsive, premium cards with loading skeleton and pull-to-refresh.

### Step 5: Study-Buddy Matching Engine
- Implement matching algorithm on backend: calculates compatibility score (0–100%) based on shared course, overlapping subjects, common interests, and compatible study modes.
- Discovery feed with search and multi-select subject filter chips.
- Interactive Study Request modal (Send Request with optional note).
- Requests manager screen: Incoming requests (Accept/Decline), Outgoing requests (Cancel), Accepted connections.

### Step 6: Campus Events Hub
- Serverpod endpoints to list, search, filter events by category/date, and fetch event details.
- Event registration endpoint with seat capacity validation and conflict checks.
- Event Details screen with countdown timer, organizer badge, interactive Register/Unregister button.

### Step 7: Student Communities Hub
- Serverpod endpoints for community directory and membership management.
- Communities screen with Category tabs (Tech, Arts, Sports, Academic, Social).
- Instant Join / Leave toggle with optimistic UI updates.
- Community details screen with member lists and announcements.

### Step 8: Subject Quizzes Module
- Serverpod endpoints to fetch quizzes by subject and record attempt scores.
- Clean quiz interface: 1 question at a time, timer, progress bar, instant option feedback.
- Results screen with detailed score analysis and option to review mistakes.
- Attempts history screen showing past performance.

### Step 9: Notifications, Bookmarks & Real-Time Polish
- Bookmarks local/remote sync for saved events and candidate study buddies.
- Notifications feed for incoming study requests and event reminders.
- Polish animations, page transitions, and offline/error boundary handling.
